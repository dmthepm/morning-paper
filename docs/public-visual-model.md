# Public Visual Model

Morning Paper should be shown first as a ritual and an object, not as software
chrome. The public visual promise is:

1. a real paper every morning;
2. a private newsroom behind it;
3. an algorithm the reader owns.

The project can be strange and memorable, but the strangeness must serve the
reading ritual. The cult object is the paper, the Desk Sheet, and the visible
fact that a reader can teach tomorrow.

## Hero Territories

Do not lock the public hero to one still-life scene too early. Explore these
territories, then choose with evidence from sketches.

### 1. Marked-Up Morning

The ritual hero. Show a printed Morning Paper edition beside a Desk Sheet with
real marks: circles, checkboxes, source notes, arrows, and one visible
"tomorrow changed because of this" proof note.

Why it works: the Desk Sheet becomes the interface. The magic is not that AI
made a paper; the magic is that the reader's marks become editorial taste.

Risk: if too messy, it reads as homework. If too pristine, the feedback loop
disappears.

### 2. One-Source First Edition

The adoption hero. Show one meaningful source becoming a small honest paper:
source slip, page proof, Desk Sheet mark, tomorrow's improvement.

Why it works: it lowers setup anxiety. A new user does not need ten
integrations to feel the product.

Risk: if treated too literally, it can look like a file converter instead of a
private newsroom seed.

### 3. Private Pressroom Cutaway

The ownership hero. Show the paper beside a tactile cutaway of the private
newsroom: `SOURCES.md`, `EDITORIAL.md`, `TASTELOG.md`, section specs, source
receipts, final proof, and delivery preferences.

Why it works: it makes ownership visible without becoming a software dashboard.
The reader can see where taste and source rules live.

Risk: it can become too explanatory. It should feel like a beautiful manual
plate or pressroom diagram, not onboarding SaaS.

### 4. Annotated First Edition

The trust hero. Show a rendered paper page with precise source notes, proof
marks, missing-perspective warnings, "not configured" honesty, and small
"earned ink" slips.

Why it works: it proves the paper is edited, sourced, and finite. It makes
source skepticism visible without a feed wall.

Risk: too many annotations can make reading feel like compliance.

### 5. Morning Run Ticket

The README proof hero. Show a pressroom job ticket stamped through the sequence:
doctor passed, demo printed, newsroom created, edition rendered, final editor
clean, PDF path returned.

Why it works: open-source trust comes from proof before promises.

Risk: it is more install proof than emotional hook, so it should support the
hero rather than replace it on the website.

## Selection Criteria

Score actual sketches against:

- desire: does it make the viewer want the object?
- trust: does it prove the paper exists and is source-backed?
- distinctiveness: could another AI tool plausibly own this image?
- owned-algorithm legibility: can the viewer see that taste and source rules
  are theirs?
- README usefulness: does it help a new user understand what will happen?

## Visual Motifs

These motifs are ownable and should recur across website, README, and launch
assets.

### Desk Sheet Marks

The Desk Sheet is not a companion object. It is the reader's control surface.
Marks should route visibly to taste, source, visual, delivery, or tomorrow
changes.

### Earned Ink Slips

Small source-backed notes that say why something made the page: source,
freshness, prior mention, extraction limit, and what was excluded.

### Source Slips

Small physical or file-native source artifacts: one newsletter, one URL, one
export, one repo note. They should imply ownership, not a giant feed.

### Taste Ledger

A durable record of what the reader accepted, rejected, or changed. The delight
is accountability: the system remembers taste without hiding the trail.

### Morning Run Ticket

A proof checklist for setup and daily runs. It should feel like a pressroom job
ticket: practical, stamped, finite, and verifiable.

### Proof Marks

Small marks for final editor, source health, visual QA, and delivery. They
should be sparse and useful, never decorative costume.

## Transformation Moments

The public visual system should show transformation, not just a finished
artifact.

1. Source becomes edition.
2. Reader mark becomes durable taste.
3. Durable taste changes tomorrow.
4. Missing source becomes honest source health, not fake copy.
5. Final proof becomes a delivered PDF.

The strongest assets will show at least one transformation clearly.

## Paper And Desk Scene

A morning desk scene still belongs in the system, but it should not be the only
approved answer. When used, it should show:

- a printed Morning Paper edition open enough to show real editorial furniture;
- the Desk Sheet beside it, marked with pen;
- one or two restrained source slips, file labels, or proof notes hinting at
  the private newsroom;
- one strong source visibly becoming one strong first edition.

The image should feel like something a serious reader could actually use
tomorrow morning. It should not look like software you log into.

Supporting line:

> Morning Paper turns your sources and taste into a finite daily paper you can
> read, mark up, and improve tomorrow.

## README Image Hierarchy

The README should be more trustworthy than atmospheric:

1. One selected hero from the territories above.
2. One small transformation sequence: source in, edition out, Desk Sheet back
   to taste.
3. One proof path: install, doctor, demo, setup, edition, final editor.

Do not lead the README with a wall of source types, a UI dashboard, or agent
roles. The reader should understand the object before they inspect the machine.

## Website Image Hierarchy

The website can be more art-directed:

1. A full-bleed hero from Marked-Up Morning, One-Source First Edition, or
   Private Pressroom Cutaway.
2. Closeups of the Desk Sheet, earned ink slips, proof marks, page numbers, and
   masthead rules.
3. A restrained private-newsroom layer: source files, section specs, ledgers,
   and delivery preferences.
4. A proof layer: run ticket, final editor, PDF path.
5. A small operator layer later in the page for the Assignment Board and source
   desks.

The visual rhythm should be: wake up to the paper, mark it up, let tomorrow get
better.

## Desk Sheet Role

The Desk Sheet is the novel primary interaction. It turns reading into training
without making the reader operate a dashboard.

Show it as:

- printed beside the paper;
- sparse enough to write on;
- marked with concrete choices, not a long form;
- connected to tomorrow's edition through taste, source, and delivery updates.

The deeper Assignment Board is for agents and superusers. It can be shown after
the reader understands the paper-plus-desk-sheet loop.

## First-Run Visual

Setup should be able to create a strong first feeling from one strong source.
The ideal first-run story is not "configure ten integrations." It is:

1. add or stage one meaningful source;
2. generate a real-feeling edition;
3. include a Desk Sheet;
4. show how the reader's notes improve tomorrow.

When context is thin, the system should make a smaller honest paper instead of
pretending it has a rich newsroom.

## Public Terms

Lead with:

- Morning Paper;
- edition;
- Desk Sheet;
- private newsroom;
- sources;
- The Read;
- proof;
- final editor.

Use with care:

- own your algorithm;
- source desk;
- beat;
- pressroom;
- masthead;
- ledger;
- Assignment Board.

Keep mostly internal:

- slug;
- kill;
- dummy;
- flatplan;
- pagination;
- morgue;
- hydration;
- candidate;
- queue;
- staged.

Avoid:

- dashboard;
- feed;
- pipeline;
- generic workflow;
- agent workforce;
- network or data-map language.

## Banned Public Imagery

Do not lead with:

- the Assignment Board;
- source management screens;
- agent org charts;
- collector plumbing;
- CLI verb lists;
- social-feed walls;
- fake old-time newspaper cosplay;
- private newsroom files filled with imaginary personal data;
- public jargon glossaries;
- screenshots full of panels and status widgets.

The public visual system should make people want the morning object first. The
machinery can become visible after trust and desire are established.
